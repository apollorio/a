## 1 · How a request reaches `/casa`

Five things run before a single byte of the landing page is printed. Three of
them can win the route outright, which is why `/casa` behaves differently for a
guest, a member, and a developer with `APOLLO_PANE_PRIMARY` set.

```
GET /
  └─ landing-router.php      template_redirect P4    guest → 301 /casa
  └─ mural-router.php        template_redirect P5    member → 302 /feed

GET /casa
  ├─ .htaccess               guest-home-guard.php writes the RewriteRule so NFD
  │                          Endurance Page Cache cannot serve a stale / before
  │                          PHP ever boots
  ├─ pages.php:33            rewrite  ^casa/?$  →  index.php?apollo_home_page=1
  ├─ pages.php:83            parse_request fallback for nginx (no rewrite rules)
  ├─ mural-router.php:63     logged in?  →  302 /feed          ◄── see §4, F-06
  └─ apollo-templates.php    template_include → templates/page-home.php
```

**Contested route.** `apollo-pane-engine` registers the *identical* rewrite
`^casa/?$ → index.php?apollo_casa_page=1` and ships
`apollo_pane_engine_owns_casa()`. The registry records the tie-break:

> *"Default: pane lab at `/painel-lab`; `/casa` is apollo-templates guest landing
> unless `APOLLO_PANE_PRIMARY` forces pane to own `/casa`."*
> — `_inventory/apollo-registry.json → $routing_canonical.apollo_pane_engine`

That matches the code. The registry is correct here.

## 2 · The render tree

`page-home.php` is Blank Canvas **Apollo** (bare, no `wp_head`/`wp_footer`) —
not Apollo+. It opens the document through `apollo_render_document_open()`
(`apollo-core/includes/blank-canvas-templates.php`), which emits the CDN
`core.js` that owns `:root`, `html {}`, `body {}` and `* {}`.

```
<html data-theme="light">
├─ head
│  ├─ cdn.apollo.rio.br/v1.0.0/core.js?prod=true     tokens + shell behaviour
│  ├─ cdn.apollo.rio.br/v1.0.0/js/forms.js
│  ├─ assets/css/new-home.css                        2120 lines · cell 1
│  ├─ cdn.jsdelivr.net leaflet@1.9.4                 map tiles
│  └─ <style id="apollo-home-styles">                 476 lines · cell 2  ◄── the fork
└─ body.ax-body[data-apollo-page="landing"]
   ├─ apollo_render_app_shell()   →  template-parts/app-shell.php
   │     .ax-top-blur · header.ax-top · .ax-overlay
   │     guest  → #burger  .ax-top-brand  #ic-login
   │     member → #ic-act  #ic-apps  #ic-pf  + #apps-pop + #panel-profile
   ├─ new-home/menu-fab.php        #nhMenuFab (display:none on /casa) + #nhMenuSheet
   ├─ main#apollo-home
   │   ├─ hero.php          .nh-hero          100dvh video · translateY(-15%)
   │   ├─ marquee.php       .nh-marquee-wrap  post ticker · 5-min transient
   │   ├─ tracks.php        .nh-tracks-grid   apollo_get_latest_dj_tracks(5)
   │   ├─ events.php        .nh-events-grid   a-eve-card contract + month stepper
   │   ├─ classifieds.php   .nh-mq            CPT classified ×8 · image marquee
   │   ├─ crash.php         .nh-mq            CPT local, tax local_type ∈ {crash,
   │   │                                      hospedagem, acomoda} · hostel switch
   │   ├─ map.php           .nh-map-wrap      Leaflet → mapa.apollo.rio.br
   │   └─ footer.php        .nh-footer        aprio-ft-v2 SVG wordmark
```

**Eight sections, ten parts, two style cells, one shared JS file.** The parts are
clean: each one owns its query, its lock rule and its markup, and the privacy
gates (`data-auth-required` → lightbox, never a hard redirect) are consistent
across tracks, classifieds and crash. That part of the architecture is in good
shape and the comments in `crash.php` about the accommodation CPT divergence are
exactly the kind of honesty that keeps a codebase honest.

The problem is not the parts. It is the **two style cells**.

## 4 · Findings

Ranked by what a visitor on a 360 px phone actually experiences.

### 🔴 F-01 · The topbar is forked. `/casa` re-declares 40 DS-owned rules.

`page-home.php` calls `apollo_render_app_shell()` directly instead of
`apollo_plus_open()`. `apollo-plus-api.php:128` is the *only* place that loads
`topbar-styles.php` — so on `/casa` the canonical topbar markup renders with
**none of its canonical CSS**, and the inline `<style>` block hand-rolls a
partial replacement.

Harness `B2` lists all 40. The geometry diverges from the constant CLAUDE.md
pins as non-negotiable:

| | DS (`topbar-styles.php:67`) | `/casa` (`page-home.php:410`) |
| --- | --- | --- |
| `top` | `2px` → bottom edge **58px** | `13px` → bottom edge **69px** |
| `right` | `13px` | `0` |
| `height` | `56px` | `var(--s-6, 56px)` |
| `justify-content` | *(none — `margin-left:auto` on `.ax-top-r`)* | `space-between` |
| icon em box | `calc(var(--fs-r,1) * 22px)` | `calc(var(--fsx,1) * 22px)` |

The last row is the subtle one. `--fsx` is a **page-local alias**
(`new-home.css:14`) that CLAUDE.md's `aside-styles.php` note explicitly records
as removed from the token system. The topbar on `/casa` scales off a different
variable than the topbar everywhere else, so a user who changes text size gets
two different headers depending on which page they are on.

And the fork is incomplete. `.ax-ic`, `.ax-avb`, `.ax-avb-init`, `.ax-dot`,
`.ax-overlay`, `.apps-pop`, `.panel-r` are **declared by nobody** on `/casa`.
`.ax-overlay` ships on every request and, unstyled, is a plain `<div>` in flow.
Today it is empty and 0-height so nothing shows — but the moment anyone gives it
content, or `mural-router` stops redirecting members (F-06), `#apps-pop` and
`#panel-profile` render as full-width blocks stacked above the hero.

### 🔴 F-02 · Three fixed elements lose their anchor if the CDN is slow

```css
new-home.css:49    .nh-navbar     { top:    calc(18px + var(--safe-top)) }
new-home.css:155   .nh-menu-fab   { bottom: calc(16px + var(--safe-bottom)) !important }
new-home.css:196   .nh-menu-sheet { bottom: calc(78px + var(--safe-bottom)) }
```

Nothing in this repository declares `--safe-top` or `--safe-bottom`; they come
from the CDN. When a custom property is unresolved, the declaration is invalid
**at computed-value time** — the property does not fall back to a sane value, it
reverts to its *initial* value. `bottom: auto` on a `position: fixed` element
puts it at its static position, near the top of the document.

`#nhMenuSheet` is the mobile menu on `/casa`. On a slow 3G phone — the exact
scenario `new-home.css:1890` calls its "MOBILE-FIRST SAFETY NET" — the menu can
open **over the hero instead of above the burger**. This is the single most
likely cause of *"nothing is aligned on mobile"*.

The same file already knows the answer: lines 315 and 375 write
`var(--safe-top, 0px)`, and `aside-styles.php:111` writes
`var(--safe-bottom,0px)`. Three call sites simply missed it.

### 🔴 F-03 · The month dropdown is anchored to the wrong box

```css
new-home.css:837          .nh-month-row { position:absolute; left:0; min-width:170px }
new-home.css:2072 ≤767px  .nh-month-row { left:0; max-width: calc(100vw - 36px - env(…)) }
```

`.nh-month-row` is absolutely positioned inside `.nh-month-dropdown`, which sits
**after the `EVENTOS` heading** inside `.grouped-left`. Its left edge is
therefore ~150 px into the row, but its width is capped against the *viewport*.
Right edge lands at `parentLeft + (100vw − 36px)` — roughly **150 px past the
right edge of a 360 px phone**.

It does not produce a scrollbar, because `#apollo-home { overflow-x: clip }`
(`page-home.php:543`) silently crops it. The user sees a month picker with its
right half cut off and no way to reach it. Harness `D3`.

Two further defects in the same rule: `transform: translateY(6px)` on line 865
overrides the `translateZ(0)` on line 854, killing the intended compositor
promotion; and `margin-top:10px` on line 867 fights the `bottom: calc(100% +
10px)` anchor on line 838.

### 🟠 F-04 · Real horizontal overflow in the 768–800 px band

```css
new-home.css:1001  @media (min-width:768px) { .nh-tracks-grid { margin: 0 -40px; padding: 0 40px } }
new-home.css:39    @media (min-width:768px) { .container      { padding: 0 clamp(32px,5vw,56px) } }
```

At 768 px the container gutter is `clamp(32, 38.4, 56)` = **38.4 px**, but the
rail bleeds **40 px**. The rail is 1.6 px wider than its container on each side,
and above 767 px nothing clips it — the `overflow-x: clip` guards live inside the
`≤767px` block. Small, but it is a genuine document-level scroll. Harness `D2`.

The bleed is also self-defeating below 768 px: line 2061 zeroes all four
properties, so the edge-to-edge rail the design calls for **does not exist on
phones at all** — which is the one place it was designed for.

### 🟠 F-05 · The mobile footer hides a third of itself

```css
new-home.css:2110  @media (max-width:767px) { .nh-footer { transform: translateY(32%) } }
```

`transform` does not affect layout. The footer is pushed 32 % of its own height
down, leaving a visible gap between the map and the footer, and pushing its last
third into scroll space that the document was never sized for. The comment calls
this a *"mobile-app style peeking footer"* — the intent is legitimate, the
mechanism is not. `padding-block-start` produces the same look and keeps the box
honest.

### 🟠 F-06 · `/casa` ships a members-only branch that no member can reach

`mural-router.php:63` 302s every logged-in user away from `''`, `casa` and
`home`. So on `/casa`:

- `app-shell.php`'s entire `$ash_logged` branch — `#apps-pop`, `#panel-profile`,
  the apps array, the notification count — is unreachable
- `tracks.php`, `classifieds.php`, `crash.php` each carry an
  `is_user_logged_in()` branch that never runs
- `page-home.php:625`'s `if (! $is_logged)` guard is always true

Dead in production, alive in the bundle. Either the redirect is the contract —
in which case these branches should be deleted and `apollo_render_app_shell()`
called with a `guest-only` argument — or the branches are the contract, in which
case F-01's missing panel CSS is a live bug waiting for the day someone relaxes
the redirect.

### 🟡 F-07 · `new-home.js` queries 11 ids `/casa` never prints

`#nhNav #nhProfileBtn #nhProfileDropdown #nhAppsBtn #nhAppsDropdown #nhLoginForm
#nhLoginSubmit #nh-login-user #nh-login-pass #nhNotifBadge #nhChatBadge`

They belong to the legacy `nh-navbar`, which `page-home.php:38` deliberately
suppresses via `APOLLO_NAVBAR_LOADED`. The AJAX login handler, both dropdowns
and the badge poller are shipped to every visitor and bound to nothing. Harness
`A1`.

### 🟡 F-08 · Duplicate-owner declarations inside the page itself

Harness `B1` — five selectors declared by both cells:
`body.ax-body`, `#apollo-home` (×3 in `new-home.css` alone),
`.nh-nav-btn`, and `.ax-top` / `.ax-top-blur` **both inside
`@media (max-width:767px)`**. The mobile topbar offset is written twice, in two
files, with the same values. Whichever loads last wins — exactly the failure mode
CLAUDE.md names the cardinal sin.

## 5 · ADR-001 — Stop forking the topbar on `/casa`

**Status:** Proposed · **Deciders:** valle

### Context

`/casa` is Blank Canvas **Apollo** (bare) but renders the **Apollo+** topbar
markup. The one function that pairs that markup with its stylesheet —
`apollo_plus_open()` — is the Apollo+ entry point, and calling it would also
mount the aside drawer, `html.ax-body{padding-top:56px}` and `.ax-main` gutters.
None of those belong on a full-bleed video hero. So the page took the markup and
re-wrote the CSS. That was a reasonable local decision and it is now the root of
F-01, F-02, F-08 and half the mobile misalignment.

### Options

**A · Extract `topbar-styles.php` behind its own loader.**
Add `apollo_plus_topbar_styles()` to `apollo-plus-api.php`; `apollo_plus_open()`
calls it, and so can any bare-canvas page. `/casa` requires it, deletes 40 inline
rules, and keeps a ~12-line `landing` variant for the three things that are
genuinely page-specific: transparent-over-hero, the scroll-dim colour ramp, and
the login-only right cluster.

| Complexity | Blast radius | Reversible |
| --- | --- | --- |
| Low — one new function, no markup change | Apollo+ pages get byte-identical CSS | Yes, entirely |

**Pros:** one owner for `.ax-*`; `/casa` inherits every future DS fix; harness
`B2` goes green; the fork can never silently reappear.
**Cons:** `/casa`'s topbar visually moves — `top: 13px → 2px`. That is the point,
but it *is* a visible change and it lands on production 30 s after save.

**B · Call `apollo_plus_open()` and neutralise the shell.**
Rejected: needs a `no-aside` flag threaded through the Apollo+ API, and
`html.ax-body{padding-top:56px}` would have to be un-done on `/casa`, which
re-creates the fork one layer down.

**C · Leave the fork, document it.**
Rejected: this *is* the documented state, and it produced 40 duplicate
declarations and a `--fsx`/`--fs-r` split in the token system.

### Decision

**Option A.** With one sequencing constraint: F-02 and F-03 ship **first**, on
their own. They are three-line, zero-visual-risk fixes to a live page and they
are the ones a phone user actually feels. The topbar unification ships second,
alone, so that if the header moves in a way you dislike there is exactly one
commit to revert.

### Consequences

- Easier: every future topbar change reaches `/casa` for free.
- Harder: `/casa` can no longer tune the topbar in isolation — by design.
- Revisit: `--fsx` (`new-home.css:14`) should be deleted once `.ax-*` scales off
  `--fs-r` again. It is the last survivor of a token fork CLAUDE.md already
  documented as removed.

## 9 · Pre-flight verification (all 20 registry chapters + `09-plugins/`)

Read before touching anything, as instructed. Three findings changed the plan.

### 🔴 F-10 · The single-event lightbox does not exist. The card is dead.

`events.php` printed, for guests:

```html
<a data-to="event-page" data-dir="right" data-id="123" href="#">
```

Three independent failures stack on top of each other:

1. **Nothing binds `data-to`.** A repo-wide grep returns only `data-tooltip`.
2. **`ApolloSlider` is defined nowhere.** It is *called* in six files —
   `panel-event-page.php`, `panel-acesso.php`, `panel-chat-inbox.php`,
   `panel-chat-list.php`, `panel-dynamic.php`, `panel-forms.php` — and
   declared in none.
3. **`page-home.php` includes no panel at all.** All twelve `panel-*.php`
   files are orphaned on disk.

And because `mural-router.php:63` 302s every logged-in visitor to `/feed`,
`$is_guest` is **always true on `/casa`**. So this was not an edge case — the
primary call to action of the events section scrolled 100 % of visitors to the
top of the page and did nothing else.

**Closed in 1.5.0** by `cells/lightbox-event.php`. The card is now a real link
to the event that `data-casa-event` upgrades in place, so it works with or
without JS — which `href="#"` never could.

### 🟠 F-11 · The icon system contradicts itself

`06-cdn.json` lists `remixicon` in `cdn.includes`, and the same chapter says:

> `FORBIDDEN_remixicon_css`: *"NEVER load remixicon@4.x CSS font when icon.js
> is active. Root cause of icon duplication bug."*

`/casa` uses `ri-*` classes throughout. Which of the two is live is decided
inside core.js, which the sandbox cannot read (`cdn.apollo.rio.br/v1.0.0/core.js`
404s; the real path is `/v1.0.0/core.js?prod=true` and returns a binary blob).
Not actionable from here — flagged for a live check.

## 10 · What shipped — v1.5.0 · the cell architecture

`templates/template-parts/new-home/cells/`

| File | Owns |
| --- | --- |
| `_manifest.php` | the catalogue and the load contract. No markup, no CSS, no behaviour — the socket board. Filter: `apollo/casa/cells`. |
| `motion.php` | `window.ApolloCasaMotion`, the Lenis ↔ ScrollTrigger marriage, and `[data-casa-reveal|stagger|parallax|mask]`. Owns **no selector** — it reads attributes off boxes other cells own. |
| `lightbox-event.php` | `.cev-*`, `window.ApolloEventLightbox`, `[data-casa-event]`. |

**The lego contract.** A cell declares `id · file · owns · needs · layer ·
guest`. `apollo_casa_render_cells($layer)` resolves `needs` topologically,
refuses to emit twice, and logs — rather than fatals — on a missing file.
Removing a cell from the manifest removes it from the page completely: no
orphan selector, no orphan listener, no console error. That round trip is the
only real test of "plug n play", and it is the one the harness now enforces.

**Motion degrades in four tiers**, because a CDN is not a guarantee:

| Tier | Available | Result |
| --- | --- | --- |
| 1 | GSAP + ScrollTrigger + Lenis | scrubbed parallax, synced smooth scroll |
| 2 | GSAP + ScrollTrigger | full motion on native scroll |
| 3 | GSAP only | IntersectionObserver reveals |
| 4 | nothing / reduced motion | everything visible, instantly |

The pre-state that hides content is scoped to `html.casa-motion`, a class JS
adds in its own first statement. If the script never runs, the class never
lands and nothing is ever hidden — plus a 3 s backstop un-hides anything the
observer missed. Hiding content behind a class you only add when you can also
remove it is the difference between a reveal and a blank page.

**Flip, in three tiers too.** `Flip` present → the modal hero animates from the
tapped card's artwork, so the event grows out of the thing you touched.
GSAP only → spring from the card's centre. Neither → the CSS transition
already in the stylesheet.
