What the audit found beyond the rubric

Ranked by what it costs, not by how hard it is to fix.

Two calls in the first version of this audit were wrong, and the correction matters more than the original claim. .carousel-item is not a fossil and type="ticket" is not a stray typo: the live markup matches the design mockup's own selector, article[type=ticket].carousel-item, and apollo-adverts already ships the CSS that animates it — assets/css/marketplace/_carousel-{desktop,tablet,sm,xs}.css plus _ticket-grid.css, with carousel-state.js and filter-toggle.js reading the same class. That handle is registered at src/Plugin.php:341 and enqueued on exactly one screen: create-classified.php:23. Renaming either hook is a coordinated six-file change, not a cleanup.
★

The screen had no gutter at any widthfixed

Rendered the real card partials through PHP 8.4 with a WordPress stub and measured them in a browser at 390, 768 and 1280. The first card's left edge was x = 0 at all three, and the page overflowed horizontally by 2px on a phone — a 392px card inside a 390px viewport. The Apollo+ shell is full-bleed by contract, so the screen owns its gutter, and .mk-screen declares only CSS variables: no padding, no margin. Cards ran into the glass, which clipped the ticket's own perforated edge and rounded corners — the detail that makes it read as a ticket.

Now padding-inline: max(16px, env(safe-area-inset-…)). Measured after: overflow 0, left 16, at every width. Column counts held by lowering the auto-fill floor 20px, so no breakpoint was silently re-laid-out.

★

Touch devices were stuck in :hoverfixed

The screen's stylesheet contains zero occurrences of any hover or pointer media feature. Every :hover rule therefore also fires on tap, and on a touchscreen nothing takes it away until you tap elsewhere — the card stays lifted and the image stays scaled. Rather than rewrite rules that are correct for a mouse, the patch cancels their effect under @media (hover:none) and gives touch its own brief :active feedback, driven by --mk-ease-snappy — a token the file declares and had never once used.

Also fixed: .btn-accom measured 29px tall and is now 44px; .ticket-tourname had no styling at all on this screen.

1

Every stay shows ★ 4.5, and no one has ever rated onetrust

The card reads get_post_meta('_classified_rating') ?: '4.5' and then renders a filled star with that number, unconditionally. I checked whether anything writes that key: nothing does. There is no rating UI, no REST write, no importer — the meta is declared and never populated. So the fallback always fires, and every accommodation listing on the site displays a review score that does not exist. This is not a styling gap; it is a number a visitor will reasonably believe.

card-accommodation.php:38 and :63 · key declared twice, at apollo-core/src/Core/MetaRegistry.php:924 and apollo-adverts/includes/constants.php:101

2

The stay card cannot be reached by keyboard at alla11y

The ticket card is a proper target — tabindex="0", role="link", an aria-label naming the advert. The stay card has the same data-mk-permalink click handler and none of that: no tabindex, no role, no label. A mouse opens it; a keyboard cannot. Two cards on one screen, sharing one JS handler, disagreeing about whether keyboard users exist.

card-accommodation.php:47-55 vs card-ticket.php:47-60

3

A link inside a link, on the card that is accessiblea11y

The ticket card carries role="link" on the <article> and then nests a real <a> (the chat button) inside it. Nested interactive controls are ambiguous to assistive tech, and the inner click also bubbles into the card's own navigate handler — so the seller-chat button and “open the advert” compete for the same tap.

card-ticket.php:47 (role) and :121 (the nested anchor)

4

<article type="ticket"> is invalid HTML — and load-bearingcraft

type is not an attribute of <article>. It parses, it does nothing, and it will not survive a validator or a strict sanitiser. It wants to be data-type — which is what the rest of this card already uses. But it cannot be changed alone: four stylesheets and two scripts in this plugin, and the design mockup itself, all select on article[type=ticket]. Correct it everywhere in one commit or not at all.

card-ticket.php:46

5

The carousel exists — it is just never loaded herecraft

The container is .mk-grid, a static grid — but the fan carousel your reference asks for is already written, in assets/css/marketplace/, driven by --active / --x / --rot custom properties that carousel-state.js sets per card. It is enqueued only on the create screen. Getting it onto /anuncios is an enqueue plus a filter-mechanism change — the current display:none filter would desync the engine's index maths, and the mockup already solves that with refreshItems(visibleCards).

card-ticket.php:46 · mk/styles.php:44-49

6

A third-party stock photo is the built-in fallbackcraft

When a stay has no featured image the card hardcodes an Unsplash URL. That is an external host on the critical render path of a page you own, with no loading="lazy", and it will one day 404 or rate-limit. A local placeholder costs nothing and never disappears.

What it takes to clear the bar

The gap is not polish. Two of these are data problems wearing a UI costume.

Before any of it can look right

  • Delete the rating fallback. Render the block only when a real rating exists. Then decide whether ratings are a product at all — a star score sits oddly beside NO_EGO_COUNTERS.
  • Give stays the fields the reference shows. Beds, baths, area — the amenity row cannot be built because no meta key holds those values. That is a MetaRegistry entry, not CSS.
  • Collapse the double registration of _classified_rating. Two owners, and the master registry is meant to be the only one.
  • Publish something. One ticket and zero stays is not enough surface to judge a grid, let alone a carousel.

Then the card itself

  • One breakpoint becomes a ladder. 479px alone cannot express 1.15 → 1.5 → 2 → 3 columns.
  • Split hover from touch — (hover:hover) and (pointer:fine) for the scale, (hover:none) for the :active equivalent. Right now a phone gets a hover state it can never leave.
  • The active-slide focus is the whole idea. The reference's footer collapsing on inactive slides is what makes it read as a carousel rather than a row. It is one max-height transition.
  • Namespace the ticket card. .top, .bottom, .rip and .barcode are four global names one plugin away from a collision.
  • Lazy-load every card image and give the media an aspect-ratio so the grid stops shifting as photos arrive.
