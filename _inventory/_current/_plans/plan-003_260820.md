## 1 · Strategy

### The one sentence, unchanged

> **One concept, one declaration, one owner. Every consumer reads it from there.**

Every defect this ecosystem has produced is that sentence violated: 107 conflicting
design tokens, two head builders, two `_dj_tracks` schemas, three canvas shells, a
reveal-selector list living in three files, a follow button existing twice so the fix
only landed on one of them.

### The three laws every phase obeys

**1 · Single owner, guard-enforced.** A second implementation must *self-disable*, not
compete. `if ( ! defined( 'APOLLO_PLUS_TOPBAR_STYLES' ) )` is the shape. Not a
convention — a constant, checked by both paths.

**2 · Fail closed and loud, never quiet.** A missing dependency degrades to a plain
link, not a blank screen. A record you know is broken is refused at the write boundary
with a real status code, not written and forgotten. Diagnostics go to `error_log`
behind `WP_DEBUG`, never to production output.

**3 · Cells, not plugins.** Extreme modularity means *many files, few plugins*. The
portal directory is the proof: 19 files, one concern each, one owner each, all inside
apollo-events. Every phase below replicates that pattern **inside an existing plugin**.
No new plugin ships in this plan.

### What "PRO mobile app" means, concretely

The product is a phone app. The desktop is a secondary client and gets correctness,
not attention. "Done" is not a feeling:

```
apollo-guard --rule M01,M02,M03,M04,M05     clean
apollo-guard --rule M06                      ladder only: 480 · 768 · 1000 · 1400
apollo-guard --harness                       5 green / 0 red
Lighthouse mobile, /casa and /eventos        Installable ✓ · Performance ≥ 90
airplane mode on /casa                       renders the shell, not the dinosaur
a card tap on /eventos, on a real phone      opens as one continuous motion
```

### What this plan refuses to build

- **`apollo-single-page`** — unifying event/dj/local single templates into one plugin
  produces a switch statement over `_event_ticket_status` / `_dj_tracks` /
  `_local_gallery` and hands one plugin the SEO and schema of every entity. Worse
  coupling than today. Phase 8 gets the same benefit through shared *helpers* while
  CPT-specific meta stays home.
- **`apollo-pwa`** — a phantom registry entry that was never built. The PWA is ~200
  lines and belongs in apollo-core, where the head already lives. Retire the entry.
- **A separate `contract-test.mjs`** — see §2. The scanner already exists.
- **A list ⇄ grid switch** — already shipped as `.pev-view-toggle` + `sectionViews`.
  It needs documenting as a contract, not building.

## 2 · Method

### The loop, every task, no exceptions

```
1  READ      the phase's to-dos and the files they name. Nothing else.
2  PLAN      if the task is marked ⊕ plan — apollo-core, apollo-templates,
             apollo-admin, apollo-pane-engine (24–31 dependents each), the HIGH
             security band (login, events, membership), or any migration that
             moves a declaration between plugins.
3  BRANCH    git -C plugins worktree add ../wt-<phase> phase/<n>
             ../wt-* is NOT mirrored to production. That is the whole point.
4  CELL      one file, one concern, one owner. Header states the ownership.
             Delete the old declaration IN THE SAME COMMIT as the new one.
5  GATE      apollo-guard for the rules the phase names, plus the phase's harness.
6  MERGE     git merge into the plugins/ checkout. THIS is the deploy — ~30s.
7  VERIFY    the phase's Test line, on a real phone, before starting the next phase.
```

### One phase per session

Each phase below is a clean stopping point with a green gate. That is not a
preference, it is a constraint: **this folder deploys on save with no staging tier**,
so a phase abandoned half-way leaves two owners of one selector in production. The
previous portal session ended exactly there and correctly refused to start the
masthead swap — that refusal is the standard, not the exception.

If you are running low on room, **stop at the last green gate and write what you
learned into the phase's to-do list.** A phase that hands over cleanly is worth more
than a phase that gets 70% done.

### What a "cell" is

```
one file · one concern · one owner
header comment states what it owns and what it must NOT declare
no selector, field name, route or schema declared by any other cell
loader (styles.php) fixes cascade order; last-word cells are named there
a harness assertion exists for whatever the cell just made impossible
```

### Definition of done, per task

A task is done when: the gate command returns clean, the phase harness is green, the
old declaration is deleted (not commented out), the registry chapter is updated if a
version or route changed, and the Test line has been performed on a phone.

## 3 · Structure — the phase ladder

Each phase unlocks the next. The order is chosen so that the riskiest work happens
last, when the guards protecting it are strongest.

| # | Phase | Unlocks | Source |
|---|---|---|---|
| **P0** | Stop the line | everything — nothing is recoverable before it | plan-001 |
| **P1** | The gate | every later phase's ability to prove itself | brainstorm Ph0 |
| **P2** | One head, one shell | the PWA, SEO, and analytics on every page | plan-002 A + plan-001 H |
| **P3** | Installable | the app icon; the thing the user actually asked for | plan-002 B |
| **P4** | Boundary hardening | safe cross-plugin work in P5–P8 | brainstorm Ph1 |
| **P5** | The popup contract | plug-and-play entity opening, ecosystem-wide | brainstorm Ph2 + lightbox P1–P5 |
| **P6** | Phone layout contract | the ladder, dvh, tap targets, the drawer | plan-002 C |
| **P7** | Weight | first-paint on 4G | plan-002 W |
| **P8** | Cells | the masthead swap becomes safe | brainstorm Ph3–5 |
| **P9** | Helpers + registry truth | one API across CPTs; the registry stops lying | brainstorm Ph6 + plan-001 T/R |

### The insight that reorders the brainstorm

The brainstorm wanted the Rail Flow masthead **and** wanted `app.php` split last,
because splitting is the riskiest work. Both are right, and together they are a
deadlock: the masthead markup lives inside `skeleton()` inside a 1,168-line IIFE, so
swapping it *is* touching the monolith.

**Resolution: split the masthead seam out of `app.php` FIRST, as its own cell, with
zero behaviour change. Then swap the cell.** Two safe steps instead of one dangerous
one. The harness assertion that guards the masthead contract stays green through
step one, and step two has a single owner from the start. That is why the masthead
sits in P8 and not earlier — and why P8's first to-do is a no-op extraction.

# PHASE 1 · The gate

**Goal.** One scanner that can prove any later phase did what it claimed.
**Why now.** Every phase below cites a gate command. If the gate is weak, the plan is
decoration.

### The correction to the brainstorm

The brainstorm proposes building `_sandbox/contract-test.mjs` with checks C1–C5.
**Do not build a second scanner.** `_inventory/_current/apollo-guard.mjs` already
exists, already runs from the real root over 1,772 files in under 40s, already has a
severity contract, a baseline mechanism, a `--staged` mode wired into the pre-commit
hook, and 24 rules. C2 is *already implemented* as rule `G08` — with a brace-matching
parser, not a regex, precisely because the naive version produced false positives on
multi-method routes. C3 exists in a `/casa`-specific form inside
`apollo-templates/_sandbox/build-casa-harness.mjs`.

**Add C1, C3-ecosystem, C4 and C5 as guard rules in the `C` series.** One scanner, one
severity ladder, one baseline. A second scanner is a second owner.

### To-do

- [ ] **P1-1 · `C01` hook arity.** Every `do_action( 'apollo/…', $a, $b )` vs every
      `add_action( 'apollo/…', $cb, $prio, $accepted )` and the callback's declared
      signature. Mismatch = CRITICAL. This is the class that produced the publish
      fatals — a listener declaring more parameters than the dispatcher sends is a
      fatal on a screen nobody opens until a user does.
- [ ] **P1-2 · `C02` cross-plugin call guard.** An `apollo_*()` call in plugin X where
      the function is defined in plugin Y, not wrapped in `function_exists()` and not
      listed in a declared manifest. HIGH. Load order is not a contract.
- [ ] **P1-3 · `C03` selector ownership, ecosystem-wide.** Lift the duplicate-selector
      detector out of the casa harness into a guard rule so it covers all 41 plugins,
      not one screen. Reuses the same parser; MEDIUM by default, CRITICAL for the
      DS-owned selector list (`.ax-*`).
- [ ] **P1-4 · `C04` registry ⇄ route truth.** `09-plugins/*.json` routes vs live
      `route_map()`. MEDIUM — this is the class that let `/feed` stay ambiguous for
      months.
- [ ] **P1-5 · Wire `--harness` into the merge ritual,** not the pre-commit hook. Five
      harnesses take longer than the edit; a slow hook gets bypassed, and a bypassed
      hook is worse than none.
- [ ] **P1-6 · Re-baseline.** `--write-baseline` after the new rules land, so the hook
      blocks new breakage only.

**Gate.** `apollo-guard --rule C` runs clean or every finding is whitelisted with a
reason. **Test.** Deliberately break one hook arity in a worktree; `C01` catches it.
**Risk.** A noisy new rule gets the whole gate ignored. Any rule that cannot be
mechanised honestly ships as MEDIUM, never CRITICAL.

# PHASE 6 · The phone's layout contract

**Goal.** The screen behaves like an app, not a page that shrank.

### To-do

- [ ] **P6-1 · One breakpoint ladder: 480 · 768 · 1000 · 1400.** 54 distinct
      breakpoints exist outside it. `max-width:767px` **and** `max-width:768px` both
      ship — at exactly 768px a max- rule and a min- rule both apply. 1000 is not
      negotiable; it is where the Apollo+ aside pins.
- [ ] **P6-2 · `100vh` → `100dvh`** on 30 boxes across 16 plugins, while 37 files
      already use `dvh`. `100svh` where the layout must not jump.
- [ ] **P6-3 · The lightbox's horizontal axis.** The panel is `100dvh` — correct — but
      `--ev-lb-w: 100vw`, `--ev-vw: 100vw`, `width: 100vw`
      (`styles-lightbox.php:127,128,133`). `100vw` ignores a classic scrollbar and
      overflows. Use `100%` of a positioned parent, or `100dvw`.
- [ ] **P6-4 · Back closes the sheet.** A phone user expects the system Back gesture to
      dismiss an overlay. Push a history entry on open, pop on close, and handle
      `popstate`. Without it, Back leaves the page entirely and the card list is gone.
- [ ] **P6-5 · Drag-to-dismiss** on the panel, with a grab affordance. This is the one
      interaction that makes a web overlay read as native.
- [ ] **P6-6 · Tap targets and the drawer.** Every control ≥ 44×44 CSS px — the topbar
      is 56px, so verify the buttons inside it, not the bar. Then: swipe-to-close,
      focus trap, `inert` on the page behind, and the overlay not scrolling the body
      underneath — the one iOS bug every drawer has.
- [ ] **P6-7 · Give pinch-zoom back.** ⊕ decision. Seven viewport tags carry
      `user-scalable=no, maximum-scale=1`, two of them in apollo-core. WCAG 2.1
      SC 1.4.4. iOS has ignored it since iOS 10; Android honours it, so the only people
      it affects are the ones who need it. `touch-action: manipulation` is the targeted
      fix and is already used in 8 plugins.

**Gate.** `--rule M03,M04` clean · `--rule M06` strictly decreasing.
**Test.** On a real phone: rotate, open the keyboard on a form, open and Back out of a
lightbox, drag it closed, and pinch.

# 10 · The agent roadmap

## 10.1 · Tier policy — what decides the model

The rule is not "hard vs easy". It is **what happens if the agent is wrong**.

| Tier | Runs when | Because a mistake is | Never |
|---|---|---|---|
| **Haiku** | the rule is exact, the target list is enumerated, and a guard rule proves the result | *caught by the gate*, mechanically | anything requiring knowledge of what the code means |
| **Sonnet** | judgement inside a bounded, named file set — and a harness or guard can check it after | *caught by review or a harness*, cheaply | apollo-core, apollo-templates, or a migration between plugins |
| **Opus** | ⊕ plan work: 24–31 dependents, the HIGH security band, or a declaration moving between plugins | *a production outage with no rollback* | mechanical sweeps — it is waste |

Two hard limits, whatever the tier:

- **No agent writes to `plugins/` directly.** Every agent works in `../wt-<phase>`.
  The merge into `plugins/` is a human act, because it is the deploy.
- **Every write-agent ends by running its gate and pasting the output.** An agent that
  reports "done" without a gate transcript is not done.

## 10.2 · The bridge preamble — paste into every agent prompt

on timeouts.

  · cd to the root, then target ONE plugin dir or SPECIFIC files.
  · sed -n 'A,Bp' f  |  grep -n 'p' f  |  rg -n 'p' apollo-events/ -g '*.php'

## 10.4 · The three agent contracts

**MAP (Haiku).** *Read only.* Output is a table of `file:line → exact text`. It never
proposes, never designs, never edits. Its value is that the next agent does not spend
its context finding things. Schema: `{area, findings:[{claim, verdict, evidence,
consequence}], surprises:[]}` — `surprises` is where it earns its keep, because the
brainstorm's biggest errors were all things nobody thought to ask about.

**APPLY (Haiku or Sonnet).** Gets an enumerated target list from a MAP agent — never
finds its own targets. Before editing, copies the original to
`_to_delete/backup-<phase>/`. After editing, runs the gate and pastes the output.
Refuses and reports if a target's line does not match what MAP said was there.

**CHALLENGE (Sonnet).** Given a finding, its job is to **refute** it. Default to
refuted when uncertain. This is the agent that caught, this session, that
`apollo-events/includes/functions.php:274` was a comment describing a removed beacon,
not a live one — a finding that had already reached a published report.

## 10.5 · Orchestration shape

```
MAP (Haiku, parallel, one per area)
  └─→ CHALLENGE (Sonnet) on any finding that would change the plan
        └─→ APPLY (tier by blast radius, one worktree per phase)
              └─→ GATE  (apollo-guard --rule …  +  --harness)
                    └─→ human merge into plugins/   ← the deploy
                          └─→ TEST on a real phone
```

**Pipeline, not barrier.** A finding that is already verified should not wait for its
five siblings before an APPLY agent starts on it. The only real barrier is the merge.

## 10.6 · The watchdog

Every fan-out gets a stall detector, because a slow network mount produces a failure
that looks exactly like work:

```
· emit on every journal line   → progress is visible
· emit STALL after ~4.5 min of silence, with the last known counts
· emit HEARTBEAT every ~15 min → silence is never ambiguous
```

Without it, an agent stuck in a 45s-timeout retry loop is indistinguishable from an
agent thinking. This session lost a six-agent fan-out to exactly that.

## The question that was asked

*"Is Blank Canvas Apollo / Apollo+ mobile-first, ahead of Figma and Apple?"*

**No — and the reason is structural, not cosmetic.** Every tab tap in production is a
full document reload. `aside.php:14` says so in its own comment: *"real WordPress URLs,
not the mockup's #/hash routes."* The reference layout swaps a `<div>` through
`app.shell.js`'s hash router; production re-fetches the HTML, re-parses `<head>`,
re-runs the external `core.js`, and rebuilds the topbar and aside from scratch. Fix every
meta tag and tap target on the list below and it will still feel like a website with a
good header, because the thing that makes an app shell feel native — content changing
while the chrome never leaves the screen — has not been built.

The polish gaps are real but they are a different category, and four of them were closed
today.

## /casa — why the harness is red, and it is not the harness

31 assertions, all true positives. The harness is dated 2026-08-08; every file it names
was edited **today**, so this is the opposite of the stale-spec hazard — and every path it
reads still resolves.

The root cause is one sentence, and `page-home.php`'s own header already confesses it:
**/casa never loads `topbar-styles.php`, so it carries a private copy of the shell's topbar
CSS — and the copy has drifted.** DS says `.ax-top{top:2px;right:13px}` and
`.ax-top-blur{height:78px}` with a mask; casa's copy says `top:13px;right:0` and
`height:60px`, no mask. Same `z-index` by luck. Nine `.ax-*` selector groups are forked
this way, plus five genuine two-file duplicates and one dead `.nh-nav-btn`.

**This was specified and deliberately not shipped.** Loading the DS cell and deleting the
private copy will visibly move /casa's topbar — correctly, into line with every other
Apollo+ page — and no browser is connected to look at it. `php -l` makes fatals impossible;
it says nothing about whether a header lands 11 px lower. The ordered 7-step fix is
recorded and ready.
