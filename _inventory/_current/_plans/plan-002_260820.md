## 0 · Start here: most of the work is already done

This matters, because "make it a PRO mobile app" sounds like a rewrite and is not.
`apollo-core/includes/document-head.php` already emits, on every canvas page:

```html
<meta name="viewport" content="… viewport-fit=cover, interactive-widget=overlays-content">
<meta name="mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<meta name="apple-mobile-web-app-title" content="…">
<meta name="theme-color" … media="(prefers-color-scheme: light)">
<meta name="theme-color" … media="(prefers-color-scheme: dark)">
<meta name="format-detection" content="telephone=no">
```

The comment above that block says *"PWA metas for app-like behavior"*.
`interactive-widget=overlays-content` in particular is the modern keyboard hint
that most production sites still do not set. `env(safe-area-inset-*)` appears in
9 plugins. 37 files already use `dvh`. The Apollo+ shell already collapses the
aside into a drawer below 1000px.

**Somebody built this for a phone.** Three things were never finished, and each
is small:

| Missing | Consequence today |
|---|---|
| a manifest, and a `<link rel="manifest">` | **Android offers no install prompt at all** |
| a root-scoped service worker | no offline, no app-shell cache, no instant relaunch |
| `apple-touch-icon` | the iOS home-screen icon is a screenshot |

iOS half-works off `apple-mobile-web-app-capable`. That is exactly why nobody
noticed Android gets nothing.

## 2 · Lane A · one head, one shell — the precondition ⊕ plan

### `A-1` · Collapse the two head builders
- **risk** high — this is apollo-core, ~31 dependents
- There are two, and they are not equivalent:

  | builder | fires |
  |---|---|
  | `apollo_render_document_head()` — `document-head.php` | `apollo/seo/head`, `apollo/canvas/head` |
  | `apollo_render_blank_canvas_open()` — `blank-canvas-templates.php` | **nothing** |

- Consequences already live, not hypothetical: any page rendered through the
  second builder gets **no SEO head**, and **no `apollo/canvas/head`** — which
  is where `apollo-statistics` hooks its tracker at priority 99
  (`apollo-statistics/src/Plugin.php:287`). **Those pages are not being
  measured.** Nobody reported it because nothing errors.
- The viewport meta, the PWA metas, the theme-color pair and the `:root{}`
  placeholder are **duplicated verbatim** between the two files and kept in
  sync by hand. This is the cardinal sin, in apollo-core, in the file that
  every screen loads.
- **do** make `apollo_render_blank_canvas_open()` delegate its `<head>` to
  `apollo_render_document_head()`. Keep the function name — it has callers.
- **gate** both shells fire `apollo/canvas/head`; the statistics tracker appears
  on every canvas page; `--rule M03` drops from 7 to 5 (the two core copies
  become one).

> Everything in lane B depends on `A-1`. Injecting `<link rel="manifest">` on
> `apollo/canvas/head` before `A-1` lands it on **half** the pages, which is
> worse than not shipping it: a manifest that appears intermittently teaches
> the browser not to offer the install prompt.

## 3 · Lane B · installable

### `B-1` · Ship the manifest and the root worker
- **rule** M01 · M02 · **risk** medium · **file** `../apollo-pwa-dropin.php`, written and reviewed, not wired
- Move to `apollo-core/includes/pwa.php`, `require_once` it, bump
  `APOLLO_CORE_VERSION` **and** the docblock together, save permalinks once.
- What it does:
  - `/manifest.webmanifest` and `/sw.js` answer from the **site root** via
    rewrite. Root scope is the whole point — a worker served from
    `/wp-content/plugins/…/assets/` can receive push but can never control a
    page, which is the state apollo-remind is in today.
  - `Service-Worker-Allowed: /` on the worker response; `no-store` on the
    worker itself, because a stale worker is the one bug you cannot push a fix
    for.
  - `start_url: /casa?source=pwa` — a PWA that launches on the marketing page
    is a bookmark, not an app.
  - `display: standalone`, not `fullscreen`. Fullscreen buys 24px and costs the
    clock and the battery indicator; people notice the loss more than the gain.
  - Four shortcuts: Eventos · Mensagens · Mapa · Meu hub. Android shows four.
  - Caching, deliberately conservative: documents network-first with a 4s
    timeout and an `/offline` fallback; CDN and same-origin static assets
    stale-while-revalidate; **`apollo/v1` never cached** — a stale line-up is
    worse than an error; cache names carry `APOLLO_CORE_VERSION`, so a version
    bump evicts everything, which is the manual escape hatch.
- **still to produce:** the icons the manifest points at —
  `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` (~20% padding or
  Android crops the logo), `apple-touch-icon-180.png`, on
  `cdn.apollo.rio.br/v1.0.0/img/pwa/`. And an `/offline` page — one Apollo+
  screen that needs no data.
- **gate** Lighthouse "Installable" passes on Android Chrome; `/sw.js` returns
  `Service-Worker-Allowed: /`; airplane mode on `/casa` renders the shell.

### `B-2` · Retire the scope-locked worker
- **rule** M02 · **risk** low, but it touches live push subscriptions
- `apollo-remind/assets/js/push-sw.js` handles push correctly and can do nothing
  else. The drop-in carries the same push and `notificationclick` contract at
  root scope. Point `apolloRemind.swUrl` at `/sw.js`, delete the old file, and
  **keep the existing subscriptions** — the endpoint does not change when the
  worker does, but re-subscribe on next visit anyway to be safe.
- **gate** a push arrives with the app closed, and tapping it opens the right URL.

## 4 · Lane C · the phone's layout contract

### `C-1` · One breakpoint ladder
- **rule** M06 · **risk** low per file, high in aggregate — do it per plugin
- **54 distinct breakpoints.** `max-width:640px` (33), `min-width:1024px` (24),
  `min-width:720px` (18), `max-width:767px` (15), `min-width:900px` (15),
  `min-width:600px` (10), `max-width:900px` (9), `max-width:782px` (7),
  `min-width:980px` (7), `max-width:960px` (6)…
- **`max-width:767px` and `max-width:768px` both exist.** At exactly 768px a
  `max-width:768px` rule and a `min-width:768px` rule both apply. That is not a
  style choice, it is a coin flip.
- The ladder, and it should go in `DOCTRINE.md` next to the token rule:
  **480 · 768 · 1000 · 1400**. 1000 is not negotiable — it is where the Apollo+
  aside pins, already documented in `CLAUDE.md`.
- **gate** `--rule M06` strictly decreasing per merge.

### `C-2` · `100vh` → `100dvh`
- **rule** M04 · **risk** low, visible immediately on a phone
- 30 boxes across 16 plugins still use `100vh`, while 37 files already use
  `dvh`. On a phone `100vh` is the *large* viewport, so the bottom of every one
  of those panels sits under the browser toolbar until you scroll.
- `100dvh` for full-height panels; `100svh` where the layout must not jump as
  the toolbar hides.
- **gate** `--rule M04` clean.

### `C-3` · Give pinch-zoom back ⊕ decision
- **rule** M03 · **risk** none technically; it is a product decision
- Seven viewport tags carry `user-scalable=no, maximum-scale=1`, including both
  apollo-core head builders. The comment says *"lock zoom"*, so this was
  deliberate — but it is a **WCAG 2.1 SC 1.4.4 failure**, iOS has ignored it
  since iOS 10, and Android honours it, so the only people it affects are the
  ones who need it.
- The targeted fix for the thing you actually wanted to prevent — double-tap
  zoom on buttons — is `touch-action: manipulation` on those elements. It is
  already used in 8 plugins.
- **This one is yours to decide, not mine to apply.**

### `C-4` · Tap targets and the drawer
- Audit every control the phone layout exposes against 44×44 CSS px. The
  topbar is 56px with icon buttons inside it; verify the buttons, not the bar.
- The aside is a drawer below 1000px driven by `#burger` / `#ax-overlay`. Verify:
  swipe-to-close, focus trap while open, `inert` on the page behind, and that
  the overlay does not scroll the body underneath — the one iOS bug every
  drawer has.
- **gate** a manual pass on a real phone, recorded in this file.

## 5 · Lane W · weight

### `W-1` · Stop shipping the desktop payload to phones
- **rule** M05 · **risk** low
- **289 `<img>` tags, zero `srcset`.** Every phone downloads the full-size file.
  The images live on `cdn.apollo.rio.br`; if it can take a width parameter,
  this is a helper function and a find-replace, not a redesign.
- Add `loading="lazy"` where it is still missing (97 files already have it) and
  `decoding="async"` alongside.
- **gate** `--rule M05` clean.

### `W-2` · The auth screen ⊕ plan
- apollo-login ships **145 KB of CSS in two files** (`apollo-auth-uni.css` 88 KB
  + `apollo-auth-complete.css` 57 KB) and **111 KB of JS** for the first screen
  a new user ever sees. It is also a HIGH-security plugin, so this is a careful
  edit, not a quick one.
- Two of those files declare `:root` (plan-001 · `K-3`) — **do the token
  collapse and the weight cut in the same pass**, they are the same files.
- **gate** first-screen CSS under 40 KB; login interactive under 2.5s on a
  throttled 4G profile.

### `W-3` · Lenis on touch ⊕ decision
- Lenis smooth-scroll is initialised in 29 files across 7 plugins. On a phone it
  replaces the platform's momentum scrolling with a JS rAF loop: it costs
  battery, it fights the pull-to-refresh gesture, and it makes long lists feel
  heavier, not lighter.
- The usual answer is to keep it on pointer-fine devices and let touch scroll
  natively — `matchMedia('(pointer: coarse)')` is already used in 4 plugins.
- **Decision, not a defect.** But measure it on a mid-range Android before
  defending it.

## 6 · Lane E · the app surface already exists, pointed the wrong way

`apollo-login/src/API/AppAuthController.php` serves `/app/auth`, `/app/verify`,
`/app/revoke`, plus `GET /dj/config` and `GET /dj/permissions`, with JWT in
`src/Security/JWTAuth.php`. `apollo-dj-sync` consumes it through
`DJPermissionsController`.

**That surface was built for the apolloDJ *desktop* product** —
`02-header.json` says so: *"apolloDJ desktop SSOT … separate product; not
loaded by WordPress"*.

### `E-1` · Decide what the phone app is, before writing a line
Three options, and they are not close in cost:

| | What it is | Cost | What it buys |
|---|---|---|---|
| **PWA** | what lane B ships | days | install, offline, push. **No app store.** |
| **PWA in a native shell** (Capacitor) | the same site, wrapped | weeks | store listing, native push, camera/share sheets |
| **Native client on the REST API** | new codebase | months | everything, and a second product to maintain |

There is **no Capacitor, Cordova or React Native code anywhere** in these 1,900
files. Whichever you pick, **lane B is the first step of all three** — even the
native shell loads a web view, and it loads it faster with the worker in place.

**Recommendation: ship lane B, live on it for two weeks, then decide.** You will
know by then whether the missing piece is the store listing or something else,
and the PWA costs nothing if you later wrap it.

## 7 · What "computer" means in this cycle

Secondary, and explicitly *not* a priority — but not abandoned:

- **The apolloDJ desktop app keeps its contract.** `/app/*`, `GET /dj/config`,
  `GET /dj/permissions` and `POST /dj/session` are frozen, not deprecated. Do
  not change a signature there while the phone work is in flight.
- **wp-admin stays as it is.** `apollo-lux-panels` is the edit surface and it
  works; no desktop-only polish this cycle.
- **The ≥1000px layouts get correctness, not attention.** They must not break —
  the harnesses cover that — but no new desktop features.
- One exception, because it is cheap and it is the phone's problem too:
  `apollo-admin/assets/modera/` ships 179 `venue` identifiers in fixture data
  (plan-001 · `D-4`). That is vocabulary debt on a desktop-only screen; it can
  wait.

## 10 · What this plan deliberately does not do

- **No native rewrite.** Nothing in the measurement supports it. The head is
  already app-shaped; the gap is three files.
- **No design refresh.** The DS is coherent where it is followed; the problem is
  107 conflicting tokens and 54 breakpoints, which is a consistency job.
- **No new plugin.** `apollo-pwa` is a phantom registry entry that was never
  built (`PLUGIN-DEPLOY-MAP.md` §2). Do not scaffold it — the PWA is 200 lines
  and belongs in apollo-core, which is where the head already lives. Retire the
  registry entry instead.
