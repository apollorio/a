## 0 · How to read this

| Field | Means |
|---|---|
| **id** | stable — the tracker, the commit message and this file all use it |
| **rule** | the `apollo-guard` rule that finds it, or the harness assertion |
| **gate** | the command that must return clean before the task is closed |
| **risk** | what breaks if this is done wrong, stated before it is done |

**Severity of the plan itself.** Tasks are ordered by *what unblocks what*, not
by severity. A CRITICAL in lane 5 can wait behind a MEDIUM in lane 0, because
the MEDIUM is the thing that stops the CRITICAL coming back.

**Plan Mode is mandatory** for any task marked `⊕ plan`. Those touch
`apollo-core`, `apollo-templates`, `apollo-admin` or `apollo-pane-engine`
(24–31 dependents each), or a HIGH-security plugin (`apollo-login`,
`apollo-events`, `apollo-membership`). Everything else is one file at a time.

**The deploy rule has not changed.** `plugins/` is mirrored to production in
~30 s. Work happens in `../wt-<lane>`, which is not mirrored. `git merge` into
the `plugins/` checkout *is* the deploy.

## 10 · Rollback

Before `P0-3` there is none — that is the point of `P0-3`.

After it: every lane is a branch, every merge into `plugins/` is one commit,
and `git revert <sha>` un-deploys in the same ~30 s RealTimeSync took to
deploy it. Keep merges small enough that one revert is one decision.

Two things a revert cannot undo, so do them deliberately and once:
`R-3` (a CPT that stops being registered orphans its posts) and any table
rename in `D-1`. Both are marked ⊕ plan for that reason.
